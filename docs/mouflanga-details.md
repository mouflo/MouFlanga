# MouFlanga : détails du code (bibliothèque, tomes, torrents, Japscan…)

Sorti de `CLAUDE.md` pour l'alléger : lire la section utile avant de toucher au domaine concerné.

## Bibliothèque
- Suppression (`/api/delete`) : chapitre ou série déplacés dans `<dossier des mangas>/.corbeille/<AAAA-MM-JJ>/`, vidée après 30 jours (`CORBEILLE_JOURS`) ; refusée pendant le téléchargement de la série.

- Couverture : `cover.jpg` dans le dossier de la série (prioritaire), choisie par `/api/cover/choisir`, retirée par `/api/cover/automatique`. Chapitres manquants : trous dans les numéros lus dans les noms de fichiers (`_numero_chapitre`).
- Séries Japscan : la liste du site pointe vers le dernier chapitre (« Dandadan 247 ») → `titre_serie()` retire ce numéro ; `_dossier_serie()` renomme l'ancien dossier « Titre N ». Page Télécharger : `deja` = chapitre déjà présent (même nom de fichier après « NNN - »).

- Générique de l'anime : `_anime_de()` cherche dans le dossier des animes (`MOUFLOPENING_ANIMES`, sinon `library.paths` de `/opt/mouflopening/config.json`) un dossier au même titre (`_cle_titre` : sans année, accents ni ponctuation ; ou titre AniList). Bouton 🎵 (`/api/generique`) et « 🎵 Choisir le générique » (menu ⋯) → `<mouflopening>/?dossier=…&de=MouFlanga&retour=…` (adresses `MOUFLOPENING_URL` / `_EXTERNE`, Réglages).
- Génériques sans anime dans Emby (`generiques.py`, `.theme.mp3` caché dans la série) : « 🎵 Changer le générique » → `/api/generique/liste` (AnimeThemes, tous les OP/ED) et `/api/generique/choisir` (slug, « aucun », vide = automatique) ; choix noté `manuel` dans `data/generiques.json`, jamais remplacé. Conversion par `src/audio.py` de MouFlopening (`MOUFLOPENING_DIR`, niveau `audio.target_db` de son config.json), loudnorm en secours ; `/api/generiques/harmoniser` remet les anciens au niveau.
- 🧹 Pages parasites (`parasites.py`) : dHash 256 bits par page, groupes à ≤ 20 bits d'écart et ≥ 3 pages ; empreintes refusées dans `.mouflanga-infos.json` (`pages_parasites`, tomes vérifiés dans `parasites_verifies` par taille) ; `_boucle_parasites` (6 h) nettoie les nouveaux tomes. Retrait = même schéma que la découpe des doubles (version à côté, relue, corbeille ; `echanger_dossier` pour les fichiers partagés). 🗑 du lecteur → `/api/parasites/page`.
- Comptes : l'admin = `APP_USER` (secrets.env) ; lecteurs dans `data/utilisateurs.json` (onglet 👥 des Réglages, `/api/utilisateurs`). `auth.role()` / `auth.utilisateur()` ; un lecteur n'a que les routes de `auth.LECTEUR_OK` (403 sinon), boutons cachés par `body.lecteur`. Progression : admin `data/progress.json`, lecteur `data/progression/<id>.json` (`_fichier_progression()`) ; renommage/suppression/rangement mettent à jour toutes (`_fichiers_progression()`).
- 📮 Demandes (`demandes.py`, `data/demandes.json`) : lecteurs cherchent sur AniList et demandent ; admin accepte/refuse (`#demandes`) ; Telegram + rappels (jour/semaine/jamais, heure) lancés seulement dans `__main__`.
- Édition (`edition.py`) : `<série>/.mouflanga-infos.json` (NFO + archive d'origine notés à l'import, analyse des pages faite une fois en fond : résolution, Digital/Scan/Web deviné, `source_manuelle` via ⋯ → 🏷). Détection d'après le nom/NFO, puis format et résolution, puis blancheur des pages.
- 🧲 Torrents (`torrents.py`, `data/torrents.json`) : onglet de /telecharger (`ui/torrents.js`, `?torrent=<recherche>`) ; Prowlarr `/api/v1/search` (catégories 7000/7030/8000), qBittorrent catégorie « mouflanga » (créée seule, dossier `TORRENTS_NOK`), tag `mf-<id>` par envoi ; suivi chaque minute (`surveiller`/`traiter`, lancé dans `__main__`) : fini → copie par lien physique dans `<série>/` → `_importer_torrent` (`_lancer_import` + `_organiser`) → `setLocation` vers `TORRENTS_OK` → Telegram. Réglages → Connexions (clé/mot de passe jamais renvoyés).
- ➕ Séries suivies (`suivi.py`, `data/suivies.json`) : ajout AniList (ou demande acceptée), cartes grisées `recherchee` dans /api/library (admin) ; `suivi.boucle` (après 7 h, une fois par jour et par série surveillée) → propositions 🆕/⬆️ (Telegram, rappels via `demandes._ETAT["autres"]`). Remplacement : `_remplacer_tomes` (ancien → corbeille, lu conservé).
- 📏 Règles de recherche (23/10/2026, `regles.py`, `data/regles.json`, page `/regles`) : format = conditions `{type, valeur, inverse, obligatoire}` (titre, regex, équipe, indexeur, badge, taille_min/max ; obligatoires tous vrais + au moins une facultative vraie, comme Sonarr) ; profil = mots doit/ne_doit_pas, taille, `sources_min`, `score_min`, `score_arret`, `scores` {format: points} (sinon points du format) ; `profil_pour(serie)` n'en choisit qu'UN (celui qui nomme la série, sinon le général). `regles.filtrer(…, avec_rejets, profil)` ajoute `score`, `formats`, `rejet` (raison), `assez_bon` ; `torrents.chercher(q, tout, serie, avec_rejets, profil)` trie : refusés en dernier, sans source ensuite, puis score. `/api/regles/tester` (onglet 🧪), `/regles/modeles` (modèles de départ, profil désactivé). Prévu ensuite : téléchargement automatique si le score atteint le profil (`score_arret`).
- 🤖 Profils d'équipe auto + bouton (23/10/2026) : `regles._resolue` (série visée = plus long nom connu dans la recherche, `regles.SERIES_CONNUES` branché par app.py) ; `regles.synchroniser_equipes` + `app._equipes_par_serie` + `_boucle_equipes` (6 h) + route `/regles/equipes` : profils `auto: True` « Manga · X » (≥ 2 séries, +1000, jamais un profil à la main) ; `auto_telechargement.plan` + `POST /api/torrents/auto` ({serie} = simulation, {serie, lancer: true} = envoi, `remplacer=False`) ; `suivi.propositions_pour` compare avec `info["scores_tomes"]` (`regles.score_titre` de la provenance « Torrent : … ») et `info["arret"]`, `suivi.purger`, `suivi.plage` (Telegram). Interrupteur par série : fait le 26/10 (ligne suivante).
- 🔗 Pages de trackers (22/10/2026) : `suivi.verifier(…, apres=lecture_pages.lire_en_fond)` lit la page de chaque nouvelle proposition (5 au plus) ; `lecture_pages.lire_proposition` / `lire_page` (route `POST /api/torrents/page` : `{serie, proposition}` ou `{page, titre[, serie]}`) → `page_tracker.lire` → `presentation.analyser`. Trackers lus par leur API avec la clé trouvée dans Prowlarr (`/api/v1/indexer`, champ `apikey`, gardée 10 min en mémoire, jamais écrite ni journalisée ni envoyée au navigateur) : C411 `GET /api/torrents/<empreinte>` (Bearer ; `description` HTML, `metadata.nfoContent`, `files`), TR4KER `GET /api/torrents/<nom>?apikey=` (`classic_description` BBCode/HTML, `nfo`), The Old School (UNIT3D) `GET /api/torrents/<n°>` (Bearer ; `attributes.description` ; son `download_link` contient la clé RSS du membre : jamais gardé), ABN `GET api.abn.lol/api/Release/<n°>` (peu de chose). Un tracker sans lecteur (HD-Forever…) dit « ouvre le lien dans ton navigateur » ; on ne contourne jamais une connexion. Seules les pages dont l'hôte est celui d'un tracker actif de Prowlarr sont lues (https, sans identifiant ni port). Mémoire : `data/torrent-pages.json` (300 pages, 7 jours). Rythme par tracker dans `reseau.SERVICES` (C411 : 15 requêtes/minute au plus). Ce qui est lu complète `suivies.json` → `<série>.tracker` (`synopsis`, `auteur`, `editeur`, `genre`, `synopsis_de`) sans jamais rien remplacer, seulement si `lecture_pages.est_la_serie` (le nom du torrent, coupé avant tome/pack/langue, est un nom de la série : noms de la série, de la fiche suivie et synonymes AniList) ; chaque proposition garde `lu` (résumé affiché sur sa ligne) ou `lu.erreur` (`definitif` : jamais réessayé ; sinon après 6 h). `api_series` : synopsis du tracker après perso > officiel FR > NFO, avec `resume_source`. Démarrage : `suivi.nettoyer_liens()` (plus de lien Prowlarr gardé) puis `lecture_pages.rattrapage` (2 pages par série, 90 s après le départ). Liens de téléchargement des résultats de recherche : `torrents.publier` / `lien_de` (numéro côté serveur, 2 h ; le navigateur n'a jamais le lien de Prowlarr, seulement les magnets).
- 🤖 Torrents « comme Sonarr » (26/10/2026) : **un seul choix par tome** (`suivi.choisir` + `suivi.cle_torrent` : score, ≥ `SOURCES_SAINES` sources, pas de gaspillage (`trop <= max(2, 2 × utiles)`), tomes utiles, tomes en trop, sources ; même équipe et « a des sources » devant pour les propositions ; même ordre dans `auto_telechargement.plan`). `suivi.verifier` rejuge les propositions en attente (gardées si toujours le meilleur choix, sinon `remplacee` → ignoré), `dedoublonner`, garde toutes les « attente » + 50 traitées. Interrupteur **🤖 Auto** par série (`suivies.json` → `auto`, action `auto` de `/api/suivies`, case `#sAuto` dans `#sProps`) : `lancer(lien, titre, nom, remplacer=False, page)` pour les « nouveau » avec sources, `AUTO_MAX_JOUR` (40, compteur `auto_jour` en tête de `suivies.json`), proposition `statut=telecharge, auto=True`, Telegram `suivi.message` (📥). **Tomes en cours** : `app._infos_suivi` → `tomes_en_cours` (tomes lus dans le nom des torrents pas finis) et `en_cours` seulement si un torrent ne dit pas ses tomes (intégrale « 10 tomes ») ; `deja_pris` = tous les noms de `torrents.json` (1000 gardés) : jamais reproposés ni repris (liste noire). **Bloqués** : `torrents.suivre_avance` (`avance`/`avance_le` ; en pause/file : repart à zéro ; `ETATS_ACTIFS` sans progrès depuis `TORRENTS_STAGNATION_H`, 24 h par défaut) → `torrents.rater` (`torrents/delete` + fichiers, seulement catégorie mouflanga, état `rate`) ; introuvable dans qBittorrent → `rate` sans nouvelle recherche ; `_ETAT["apres_rate"]` = `app._apres_rate` (un message, `_verifier_serie` en fond pour les séries surveillées). **📡 Flux des nouveautés** : `torrents.flux()` (recherche vide de Prowlarr, ~500 torrents, une requête) toutes les 15 min (`suivi.boucle_flux`, `FLUX_INTERVALLE`), `suivi.series_du_flux` (un nom de série ≥ 4 lettres dans le nom du torrent, jamais vu) → `app._verifier_serie` (au plus une fois par heure, `FLUX_REPOS`). Démarrage : `suivi.nettoyer(_infos_suivi)` à 150 s (purge + doublons, même pour les séries non surveillées). Recherche « One Piece T45 » = 0 résultat sur les trackers : on cherche la série et on trie chez nous. Intégrale sans numéros : `suivi.tomes_couverts(r, attendus)` (N par `edition.volumes_du_titre`, sinon `info["attendus"]` = `_volumes_attendus`, AniList pour une série vide ; inconnu → rien).
- Séries suivies vides : `prechauffage` les prépare aussi (`_series_preparables`, `_preparer_serie_suivie` : étapes `statut` et `fiche`) ; leur fiche AniList est `suivi[nom].anilist` (`_anilist_choisi` s'y rabat).
- 🔗 Assemblage de doubles pages : `optimiser.assembler` (inverse de `couper`, même schéma : version à côté, relecture, ancien → `.avant`), `lancer_coupes(operation=assembler)`, routes `/api/doubles/tomes` et `POST /api/doubles/assembler` ({series, sens, plan:[{fichier, indices}]}, indices = 1re page de chaque paire, jamais deux paires qui se touchent) ; UI dans ℹ️ → 🪶 Alléger (`asm*` dans mouflanga.js).
- Torrents : `torrents.lier` fait une VRAIE COPIE par défaut (`TORRENTS_COPIE`, case dans Réglages → Torrents ; copie dans « .<nom>.copie » puis `os.replace`), lien physique seulement si décoché. Avant le 12/10/2026, liens physiques (ex. « Gantz : Perfect » : 18 fichiers liés à Mouflanga.OK).
- ⚠️ NAS : un fichier partagé par qBittorrent (lien physique) ne peut être ni renommé ni effacé depuis MouFluxer → `_importer_torrent` place chaque fichier directement sous son nom final (`torrents.lier`), archives dans `<série>/.torrent/`. Version : `BASE_VERSION` 2.0, numéro = commits depuis `DEPART_VERSION`.
- Accès des autres applis (`api_externe.py`) : `/api/externe/series`, `/api/externe/couverture` (GET/POST), en-tête `X-Cle-API` ; clé générée dans ⚙️ Réglages (`MOUFLANGA_CLE_API_SHA256` + 4 derniers caractères) ; ces routes passent hors de l'écran de connexion (`auth.py`). Bouton « Créer avec MouFloster » : `MOUFLOSTER_URL` → `<moufloster>/?mouflanga=<série>&q=…&retour=…`.

## Tomes (`tomes.py`, `tomes_cbz.py`)
- **Refonte du 22/10/2026 : toute la recherche sur Internet (statut, titres des tomes, chapitres, ISBN, résumés) est décrite dans `docs/identification.md`** (règles : trois issues trouvé / rien trouvé / panne, rien n'est jamais effacé, étapes expliquées, reprises automatiques ; modules `reseau.py`, `correspondance.py`, `wikifr.py`, `bnf.py`, `googlebooks.py`, `notices.py`, `identification.py`). Les lignes plus bas sur Google Books d'abord, le cache de 3 jours ou « Relancer l'identification efface le cache » sont d'avant ; ce document fait foi.
- `tomes.chercher(série)` : Wikipédia (« List of … chapters », formats Numbered list / « *12. » / « * Chapter: 1–7 » / « # », commentaires retirés, section « Chapters not yet in tankōbon ») puis MangaDex ; cache 3 jours `data/tomes/`. Wikipédia limite les requêtes (429) : rester sobre.
- Fichier de tome : `Tome NN/<Série> - Tome NN.cbz` (ou `Hors tome/`), pages `c0012.00-p003.jpg`, `chapitres.json` (titres), `ComicInfo.xml`. Réécriture complète à chaque ajout (fichier .tmp puis remplacement).
- Bibliothèque : `_entrees()` donne les chapitres (clé = chemin pour un fichier ordinaire, « #12 » pour un chapitre de tome, avec `debut`/`nb`) ; progression et « lu » par clé. `_ranger_en_tomes()` : anciens fichiers → tomes, hors tome → tome sorti ; lancé avant chaque téléchargement (`preparer`) et par le bouton « Ranger en tomes ».

- Séries ajoutées à la main : `_plan_organiser()` (nom proposé d'après les noms de fichiers, crochets et « T01 » retirés) et `/api/organiser` (`_organiser()` : renommage, tomes complets déplacés dans `Tome NN/`, progression suivie, puis rangement des chapitres en arrière-plan). `_numero_tome()` reconnaît un tome complet ; `tomes_cbz._reecrire` refuse d'écraser un fichier qui n'est pas un fichier de tome.

- Import (`importer.py`) : PDF et archives > 400 Mo (`LOT_MIN`) = « à importer » (affichés 📦, non lisibles) ; extraction avec `bsdtar` dans `<série>/.import/` sur le NAS (le disque du conteneur est petit), tome = dossier « …Tome NN… », chapitre = sous-dossier numérique ; PDF via PyMuPDF. Choix de noms retenus dans `data/organiser-choix.json` (`_appris`), option `ORGANISER_AUTO`.

- Import des archives de la racine : `/importer`, `_archives_racine()` (nom proposé `_nom_depuis_archive`), file `_FILE_IMPORT` traitée par `_travail_file()` (une série à la fois, Telegram à la fin). `importer.deplier()` ouvre les archives/PDF intérieurs ; `_classer()` : 1er dossier « tome », sinon numéro final (« MAR.07 »), sinon nom de l'image ; `repartir()` sépare les séries dont les tomes se chevauchent. Cas réels étudiés : inventaire de 72 archives du 06/10/2026.

- Marque fini/incomplet/en cours : `tomes.statut_officiel()` (AniList, choix du résultat d'après le titre et le nombre de tomes locaux, cache `statut_officiel` dans `data/tomes/<série>.json`, 7 jours), rempli en fond par `_remplir_statuts()` à l'ouverture de la bibliothèque ; `_etat_serie()` compare au NAS.

- Sommaire imprimé (`sommaire.py`) : OCR tesseract `fra` (`nice`, un cœur, un tome à la fois) des 14 premières images d'un tome complet ; lignes « SCÈNE 1 Titre ....5 » / « 12. Titre ... 45 » ; décalage page imprimée → image d'après le titre du 1er chapitre vu APRÈS le sommaire (la couverture porte souvent le même titre). Gardé dans `.mouflanga-infos.json` → `sommaires`. Lancé tout seul par `/api/tome` (admin) si aucun chapitre FR ; bouton `/api/tome/sommaire`. Sommaires stylisés (Bakuman) non lus.
- Sommaires, refonte du 26/10/2026 (lecteur version 10) :
  - **Lecture d'un tome** (`sommaire.lire`) : sommaire cherché dans les 14 premières images avec tesseract puis RapidOCR (`_lire_avec(..., placer=False)`, le second seulement si le premier n'est pas `_complet_et_sur`) ; la place des chapitres (`_placer` → `_images`) n'est cherchée qu'UNE fois, sur la meilleure lecture ; le numéro imprimé en bas des pages (`_ecart_imprime`) est lu AVANT de chercher le titre sur des pages entières (sauf page de sommaire estimée) ; les chapitres « estimee » sont confirmés par la mention de leur numéro sur la page d'ouverture (`_confirmer_ouvertures`) ; puis chaque chapitre est cherché sur sa propre page (`_verifier_leger`) et, s'il en manque un ou si les longueurs sont incohérentes (`_a_verifier`), toutes les images sont lues vite et les pages d'ouverture font foi (`_verifier_par_ouvertures` : longueur minimale = 40 % de la moyenne, ±2 pages = on garde la place lue, résultat écarté s'il est moins plausible qu'avant). Mentions « #4 » et mots courts (« ep », « match ») jamais crus de la lecture rapide (textures du dessin) ; « chapitre 36 fin », « suite au chapitre 37 » écartés ; lecteur moderne plafonné à 80 pages par tome (`BUDGET_MODERNE`).
  - **Mémoire des lectures** pendant la lecture d'un tome : `_LOCAL.memo` (tous les appels à tesseract passent par `_run`, le lecteur moderne par `_ocr_moderne`, clé = md5 de l'image + réglages) et `_pages_en_memoire` (24 images). `MEMO_DISQUE` sert seulement au banc d'essai.
  - **Tomes sans sommaire** : `chapitres_par_ouvertures` lit toutes les images vite (tesseract `--psm 11`, image réduite à 1500 px, ~0,4 s), cherche les mentions « CHAPITRE 36 », « #36 », « 88e punch », « Trick:166 », « 0333 » (`_mentions`), garde la plus longue suite qui monte (`_chaine`), puis relit au lecteur moderne les pages après une page de séparation (même image répétée : `_separatrices`) et les trous. Source « pages d'ouverture ». Format « 88º punch » / « titre page » : `analyser_numero_avant`.
  - **Éditions spéciales** (`app._edition_differente` : Perfect, deluxe, intégrale…) : `app._numeros_fiables` rend [] → seuls comptent les numéros imprimés dans le tome (règle demandée le 26/10/2026 : « si rien de fiable sur le net, on se fie à la lecture des tomes »). `app._suite_de` = dernier chapitre du tome précédent (indice, jamais un filtre : il est parfois mal lu).
  - **Relectures** : seulement les lectures périmées ET incomplètes (`app._lecture_perimee`, `_a_relire` : rien trouvé, pages estimées ou sans image, moins de chapitres que prévu). Avant, chaque nouvelle version relisait tous les tomes (3 à 4 lectures par tome) et les tomes « pages d'équipe » sans résultat étaient relus à chaque ouverture de leur fiche. `_boucle_relecture_sommaires` (30 min après le démarrage puis toutes les 6 h) relit les tomes périmés sans rien demander à Internet, quand l'appli est libre.
  - **Écritures** du fichier d'infos : `edition.VERROU` (= `app._VERROU_SOMMAIRES`, décorateur `_sous_verrou_infos`) et un fichier provisoire par tâche.
  - **Banc d'essai** : `outils/banc_sommaires.py` (`preparer`, `lancer NOM`, `bilan NOM [AVANT]`, `pages`), données dans `data/banc-sommaires/` (manifeste, pages de sommaire des tomes validés, mémoire OCR, résultats). Toujours le passer avant/après une modification du lecteur ; les tomes validés à la main font foi.
- Lecteur et chapitres d'un tome complet (26/10/2026) : `GET /api/lecteur/chapitres?s=&tome=` (permis aux lecteurs, rien d'écrit) → `ui/lecteur.js` (`interne`, `chargerInternes`, ⏮ ⏭ d'un chapitre à l'autre, ☰ `listeChapitres`). 🎯 Vérification (`/lire?...&verif=1`, administrateur, bouton sur la fiche du tome) : `POST /api/tome/chapitre_page` ({num, image?} → `verifie`, saisie, jamais validé tout seul) et `POST /api/tome/chapitres_decaler` ({apres, decalage}) ; position de lecture jamais enregistrée en vérification. Apprentissage : `_garder_places_auto` (« auto_image » à la 1re correction), `_decalage_de_serie` (≥ 5 chapitres vérifiés, 70 % même écart non nul ≤ 3), `_appliquer_decalage_appris` (lectures automatiques seulement, `decalage_appris` par tome, `decalage_chapitres` pour la série) ; les nouvelles lectures le reçoivent dans `_lire_sommaire._enregistrer`.
- Résumés : `statut_a_jour()` (7 jours si complet, 1 jour si série ou résumé manquant) ; AniList introuvable → `_titres_mangaupdates()` (nom d'origine) puis `_resume_sans_anilist()` (Wikipédia FR, MangaUpdates) ; `_sans_suites()`. Résumé d'un tome : TomeBD Wikipédia, sinon `resume_tome_google()`.
