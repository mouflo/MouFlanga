# MouFlanga : détails du code (bibliothèque, tomes, torrents, Japscan…)

Sorti de `CLAUDE.md` pour l'alléger : lire la section utile avant de toucher au domaine concerné.

## Bibliothèque
- Suppression (`/api/delete`) : chapitre ou série déplacés dans `<dossier des mangas>/.corbeille/<AAAA-MM-JJ>/`, vidée après 30 jours (`CORBEILLE_JOURS`) ; refusée pendant le téléchargement de la série.

- Couverture : `cover.jpg` dans le dossier de la série (prioritaire), choisie par `/api/cover/choisir`, retirée par `/api/cover/automatique`. Chapitres manquants : trous dans les numéros lus dans les noms de fichiers (`_numero_chapitre`).
- Séries Japscan : la liste du site pointe vers le dernier chapitre (« Dandadan 247 ») → `titre_serie()` retire ce numéro ; `_dossier_serie()` renomme l'ancien dossier « Titre N ». Page Télécharger : `deja` = chapitre déjà présent (même nom de fichier après « NNN - »).

- Générique de l'anime : `_anime_de()` cherche dans le dossier des animes (`MOUFLOPENING_ANIMES`, sinon `library.paths` de `/opt/mouflopening/config.json`) un dossier au même titre (`_cle_titre` : sans année, accents ni ponctuation ; ou titre AniList). Bouton 🎵 (`/api/generique`) et « 🎵 Choisir le générique » (menu ⋯) → `<mouflopening>/?dossier=…&de=MouFlanga&retour=…` (adresses `MOUFLOPENING_URL` / `_EXTERNE`, Réglages).
- Génériques sans anime dans Emby (`generiques.py`, `.theme.mp3` caché dans la série) : « 🎵 Changer le générique » → `/api/generique/liste` (AnimeThemes, tous les OP/ED) et `/api/generique/choisir` (slug, « aucun », vide = automatique) ; choix noté `manuel` dans `data/generiques.json`, jamais remplacé. Conversion par `src/audio.py` de MouFlopening (`MOUFLOPENING_DIR`, niveau `audio.target_db` de son config.json), loudnorm en secours ; `/api/generiques/harmoniser` remet les anciens au niveau.
- 🧹 Pages parasites (`parasites.py`) : dHash 256 bits par page, groupes à ≤ 20 bits d'écart et ≥ 3 pages ; empreintes refusées dans `.mouflanga-infos.json` (`pages_parasites`, tomes vérifiés dans `parasites_verifies` par taille) ; `_boucle_parasites` (6 h) nettoie les nouveaux tomes. Retrait = même schéma que la découpe des doubles (version à côté, relue, corbeille ; `echanger_dossier` pour les fichiers partagés). 🗑 du lecteur → `/api/parasites/page`.
- Comptes : l'admin = `APP_USER` (secrets.env) ; lecteurs dans `data/utilisateurs.json` (onglet 👥 des Réglages, `/api/utilisateurs`). `auth.role()` / `auth.utilisateur()` ; un lecteur n'a que les routes de `auth.LECTEUR_OK` (403 sinon), boutons cachés par `body.lecteur`. Progression : admin `data/progress.json`, lecteur `data/progression/<id>.json` (`_fichier_progression()`) ; renommage/suppression/rangement mettent à jour toutes (`_fichiers_progression()`).
- 📮 Demandes (`demandes.py`, `data/demandes.json`) : lecteurs cherchent sur AniList et demandent ; admin accepte/refuse (`#demandes`) ; Telegram + rappels (jour/semaine/jamais, heure) lancés seulement dans `__main__`.
- Édition (`edition.py`) : `<série>/.mouflanga-infos.json` (NFO + archive d'origine notés à l'import, analyse des pages faite une fois en fond : résolution, Digital/Scan/Web deviné, `source_manuelle` via ⋯ → 🏷). Détection d'après le nom/NFO, puis format et résolution, puis blancheur des pages.
- 🧲 Torrents (`torrents.py`, `data/torrents.json`) : onglet de /telecharger (`ui/torrents.js`, `?torrent=<recherche>`) ; Prowlarr `/api/v1/search` (catégories 7000/7030/8000), qBittorrent catégorie « mouflanga » (créée seule, dossier `TORRENTS_NOK`), tag `mf-<id>` par envoi ; suivi chaque minute (`surveiller`/`traiter`, lancé dans `__main__`) : fini → copie par lien physique dans `<série>/` → `_importer_torrent` (`_lancer_import` + `_organiser`) → `setLocation` vers `TORRENTS_OK` → Telegram. Réglages → Connexions (clé/mot de passe jamais renvoyés).
- ➕ Séries suivies (`suivi.py`, `data/suivies.json`) : ajout AniList (ou demande acceptée), cartes grisées `recherchee` dans /api/library (admin) ; `suivi.boucle` (après 7 h, une fois par jour et par série surveillée) → propositions 🆕/⬆️ (Telegram, rappels via `demandes._ETAT["autres"]`). Remplacement : `_remplacer_tomes` (ancien → corbeille, lu conservé).
- Torrents : `torrents.lier` fait une VRAIE COPIE par défaut (`TORRENTS_COPIE`, case dans Réglages → Torrents ; copie dans « .<nom>.copie » puis `os.replace`), lien physique seulement si décoché. Avant le 12/10/2026, liens physiques (ex. « Gantz : Perfect » : 18 fichiers liés à Mouflanga.OK).
- ⚠️ NAS : un fichier partagé par qBittorrent (lien physique) ne peut être ni renommé ni effacé depuis MouFluxer → `_importer_torrent` place chaque fichier directement sous son nom final (`torrents.lier`), archives dans `<série>/.torrent/`. Version : `BASE_VERSION` 2.0, numéro = commits depuis `DEPART_VERSION`.
- Accès des autres applis (`api_externe.py`) : `/api/externe/series`, `/api/externe/couverture` (GET/POST), en-tête `X-Cle-API` ; clé générée dans ⚙️ Réglages (`MOUFLANGA_CLE_API_SHA256` + 4 derniers caractères) ; ces routes passent hors de l'écran de connexion (`auth.py`). Bouton « Créer avec MouFloster » : `MOUFLOSTER_URL` → `<moufloster>/?mouflanga=<série>&q=…&retour=…`.

## Liste Japscan
- `/api/japscan/list` = dernières sorties (accueil, 6 h) + `data/mangas-trouves.json` (recherches) + `data/catalogue-japscan.json` (catalogue `/mangas/?p=1..279`, chargé par `/api/japscan/catalogue`), regroupés par `regrouper_series()`. Recherche du site : réponse JSON de `/ls/` lue en tapant dans `#searchInput`.

## Tomes (`tomes.py`, `tomes_cbz.py`)
- `tomes.chercher(série)` : Wikipédia (« List of … chapters », formats Numbered list / « *12. » / « * Chapter: 1–7 » / « # », commentaires retirés, section « Chapters not yet in tankōbon ») puis MangaDex ; cache 3 jours `data/tomes/`. Wikipédia limite les requêtes (429) : rester sobre.
- Fichier de tome : `Tome NN/<Série> - Tome NN.cbz` (ou `Hors tome/`), pages `c0012.00-p003.jpg`, `chapitres.json` (titres), `ComicInfo.xml`. Réécriture complète à chaque ajout (fichier .tmp puis remplacement).
- Bibliothèque : `_entrees()` donne les chapitres (clé = chemin pour un fichier ordinaire, « #12 » pour un chapitre de tome, avec `debut`/`nb`) ; progression et « lu » par clé. `_ranger_en_tomes()` : anciens fichiers → tomes, hors tome → tome sorti ; lancé avant chaque téléchargement (`preparer`) et par le bouton « Ranger en tomes ».

- Séries ajoutées à la main : `_plan_organiser()` (nom proposé d'après les noms de fichiers, crochets et « T01 » retirés) et `/api/organiser` (`_organiser()` : renommage, tomes complets déplacés dans `Tome NN/`, progression suivie, puis rangement des chapitres en arrière-plan). `_numero_tome()` reconnaît un tome complet ; `tomes_cbz._reecrire` refuse d'écraser un fichier qui n'est pas un fichier de tome.

- Import (`importer.py`) : PDF et archives > 400 Mo (`LOT_MIN`) = « à importer » (affichés 📦, non lisibles) ; extraction avec `bsdtar` dans `<série>/.import/` sur le NAS (le disque du conteneur est petit), tome = dossier « …Tome NN… », chapitre = sous-dossier numérique ; PDF via PyMuPDF. Choix de noms retenus dans `data/organiser-choix.json` (`_appris`), option `ORGANISER_AUTO`.

- Import des archives de la racine : `/importer`, `_archives_racine()` (nom proposé `_nom_depuis_archive`), file `_FILE_IMPORT` traitée par `_travail_file()` (une série à la fois, Telegram à la fin). `importer.deplier()` ouvre les archives/PDF intérieurs ; `_classer()` : 1er dossier « tome », sinon numéro final (« MAR.07 »), sinon nom de l'image ; `repartir()` sépare les séries dont les tomes se chevauchent. Cas réels étudiés : inventaire de 72 archives du 06/10/2026.

- Marque fini/incomplet/en cours : `tomes.statut_officiel()` (AniList, choix du résultat d'après le titre et le nombre de tomes locaux, cache `statut_officiel` dans `data/tomes/<série>.json`, 7 jours), rempli en fond par `_remplir_statuts()` à l'ouverture de la bibliothèque ; `_etat_serie()` compare au NAS.

- Sommaire imprimé (`sommaire.py`) : OCR tesseract `fra` (`nice`, un cœur, un tome à la fois) des 14 premières images d'un tome complet ; lignes « SCÈNE 1 Titre ....5 » / « 12. Titre ... 45 » ; décalage page imprimée → image d'après le titre du 1er chapitre vu APRÈS le sommaire (la couverture porte souvent le même titre). Gardé dans `.mouflanga-infos.json` → `sommaires`. Lancé tout seul par `/api/tome` (admin) si aucun chapitre FR ; bouton `/api/tome/sommaire`. Sommaires stylisés (Bakuman) non lus.
- Résumés : `statut_a_jour()` (7 jours si complet, 1 jour si série ou résumé manquant) ; AniList introuvable → `_titres_mangaupdates()` (nom d'origine) puis `_resume_sans_anilist()` (Wikipédia FR, MangaUpdates) ; `_sans_suites()`. Résumé d'un tome : TomeBD Wikipédia, sinon `resume_tome_google()`.
- MangaDex (`_mangadex`) : 50 résultats, titre identique obligatoire (jamais `data[0]`). `_ranger_en_tomes` déplace aussi les chapitres d'un tome de l'appli vers le tome indiqué par la répartition. `_rangement_complet()` sert au bouton, à la ré-identification (étape 5) et au passage automatique de `_remplir_statuts` (séries avec « Hors tome », cache des tomes passé).
- Pas de scraper manga-sanctuary.com : son robots.txt interdit Claude (`User-agent: Claude-Web`, refusé le 12/10/2026).

- Lot du 12/10/2026 soir : 🔎 fiche AniList choisie (`.mouflanga-infos.json` → `anilist_choisi`, `tomes.ID_CHOISI`) ; sources en couleur (JS `SOURCES`) ; 📎 `/api/rattacher` + `_serie_mere()` ; fusion `fusionner` = manquants | remplacer | serie ; choix retenus `data/regles-import.json` (`_regle_import`, `_appliquer_choix`) ; `_serie_proche()` à l'envoi d'un torrent ; ComicInfo enrichi (`tomes_cbz.INFOS_SERIE`) ; même équipe (`provenance.equipe_torrent/meme_equipe`, propositions `type: equipe`, remplacement auto 1-3 tomes) ; hors-séries Fandom (`hors_serie.fandom`, `apres_tome`) ; ✂️ `decoupage.py` + `/decouper` (index.json) ; 🪶 `optimiser.py` (PSNR ≥ 39 dB, largeur 1600/1200, jamais un fichier lié) ; 📱 `ui/sw.js` + `ui/hors-ligne.js` (cache `mf-hors-ligne`), Web Push `push.py` (`data/vapid.json`, `data/push.json`, `notifier.RELAIS`) ; Claude pour les sommaires stylisés (`CLAUDE_API_KEY`, `sommaire.lire_vision`) ; 🔄 `redemarrer.py` (identique dans les 4 applis, `_travaux_en_cours()`).

## Le scraper Japscan (`japscan_scraper.py`)
- Navigateur au choix dans ⚙ Réglages : Chrome (Patchright, profil `data/navigateur`) ou Camoufox (Firefox, profil `data/navigateur-firefox`), sous écran virtuel Xvfb ; clics réels avec xdotool.
- Cloudflare impose une vérification interactive : la page `/verification` montre le navigateur du serveur (capture) et relaie clics, défilement et glisser du doigt ; alerte Telegram.
- `brunhild.challenges.cloudflare.com` n'existe qu'en IPv6 et le serveur n'a pas d'IPv6 : redirection vers IPv4 (option du navigateur ou ligne `# MouFlanga-cloudflare` dans `/etc/hosts`). AdGuard Home (DNS 192.168.1.139) doit laisser passer les domaines Cloudflare.
- Fiche série : le site cache la vraie liste de chapitres sous des leurres (liens `d-none`, faux « Chapitre 000001 » invisibles par `clip-path`). On ne lit que les éléments réellement visibles (`_JS_ZONES_VISIBLES`) ; l'adresse d'un chapitre est `/manga/<série>/<numéro>/`.
- Lecteur : un captcha d'images (tranches à remettre en ordre en glissant) peut s'afficher avant les pages ; détecté par le contenu de la page (Camoufox cache les variables `window`), résolu **à la main** par l'utilisateur. Ne pas chercher à le résoudre ni à l'éviter automatiquement (refusé le 06/10/2026, Cloudflare compris). Option « captchas groupés » (`JAPSCAN_CAPTCHAS_GROUPES=1`) : 1re passe sans attendre (`CaptchaReporte`), puis une alerte et les captchas à la suite ; le rapport note « captchas : N pour M chapitre(s) » pour comparer avec le mode normal (constaté : 1 captcha sur 2 chapitres).
- Pages : capturées sur le réseau (images de `c4.japscan.foo`), rangées dans l'ordre où le lecteur les demande (les noms de fichiers n'ont pas d'ordre). Ordre vérifié à l'œil le 06/10/2026 (Dandadan ch. 1 : 63/63, couverture → « Fin »). L'appli attend toutes les pages annoncées (`select#pages`) ; lecteur vide après captcha → rechargement du chapitre.
- Un seul navigateur sert à tout un téléchargement ; arrêt automatique après 3 chapitres de suite sans page ; onglet « En cours » avec bouton Annuler.
- Liste des mangas gardée 6 h (`data/mangas-japscan.json`), chapitres 1 h en mémoire.

## Rescan du dossier des torrents et fiche d'une série vide (12/10/2026)
- `/api/import/torrents` (GET liste, POST file) : `_elements_torrents()` lit `TORRENTS_NOK`, nom deviné par `_nom_depuis_archive` (même code que `adopter`) ; `_travail_rescan()` → `_importer_torrent` + `_noter_volumes_torrent` + `_rapport_serie`, jamais d'écrasement (`_tomes_deja_la`). État dans `_RESCAN` (compté dans `_travaux_en_cours`). Page : panneau « Dossier des torrents » de `templates/importer.html` / `ui/importer.js`.
- Identification : `_titre_anilist` (alphabet latin seulement ; réponse en cache non latine refaite), `_BRUIT`/`_COUPURE` connaissent NOTAG et HYBRID, `_appris` ne retire un mot partout que s'il est technique ou retiré deux fois, auteur final écarté dans `_nom_sans_edition`.
- Série ajoutée (suivi) sans dossier : `/api/series` renvoie `recherchee: true` (+ `cover_externe`, infos dans `compte`) ; poster enregistré dans `<série>/cover.jpg` (dossier créé), servi par `/api/cover`.

## ✨ Améliorer les vieux scans (13/10/2026)
- `optimiser.ameliorer(im, "d,t,p,n,ta,l,ne,a")` (ordre `AMELIORATIONS`, 0 à 3) : débruit NLM d'OpenCV (h 4/7/10 : 14 effaçait les points de suspension), trames floutées hors des traits (`_traits` = gradient sur version floue), papier = division par le fond (fermeture sur la page réduite ×4, bornée à 85 % du papier pour ne pas blanchir les cheveux), noirs (LUT), poussières (composantes < 200 sans autre encre autour), lissage à ×2 puis retour à la taille (flou + courbe en S sur les traits seulement), netteté, agrandir ×2 (h < 1700). Couleur : jamais touchée.
- Paramètre `am=` (comparer) / `amelio` (POST). `eclairer=True` (ancien) = papier 2 + noirs 1. Dépendance : `opencv-python-headless`.
- Aperçu : `comparer` sous verrou (avant/après/infos arrivent ensemble), qualité auto de l'aperçu sur 3 pages d'essai.

## Alléger un tome partagé par qBittorrent (12/10/2026)
- Le NAS (NFS) refuse de renommer ou d'effacer un fichier lié au torrent (même après pause du torrent, même chmod), mais accepte de renommer un DOSSIER. `optimiser.reecrire_partage` : version légère dans `.<Tome NN>.allege/`, puis `Tome NN` → `.Tome NN.avant` → corbeille et `.allege` → `Tome NN`. Seulement si le tome est seul dans son dossier (`_dossier_a_lui`).


## Index de la bibliothèque (13/10/2026)
- `indexation.py` + `app._scan()` : parcours du NAS gardé en mémoire et dans `data/index.sqlite` (tables fichiers, dossiers, meta ; WAL). `_scan()` compare la date de chaque dossier connu (un stat par dossier, une fois par requête) et reparcourt seulement si elle a changé ; les écritures (POST hors `_SANS_EFFET_SUR_FICHIERS`) invalident aussi (`_scan_invalider()`). Un dossier modifié depuis moins de 2 s est revérifié (horloge du disque). `_scan()` rend une copie de premier niveau.
- `_stat_index(f)` : taille et date d'un fichier d'après l'index ; `_memo_fichier()` garde `tomes_cbz.lire_info/chapitres` par (taille, date) ; `tomes._charger` garde les fiches par (date, taille) du JSON.
- Parcours complet (tailles relues) toutes les 10 min en arrière-plan. Seul le dossier réel est enregistré dans index.sqlite (pas ceux des tests).
- Page : `drawGrid()` affiche `GRILLE_PAGE` = 36 cartes puis `grilleSuite()` (IntersectionObserver, sentinelle `#grilleSuite`).
- Piste suivante (pas faite) : données des lecteurs (progression, favoris, demandes) vers SQLite si le nombre d'utilisateurs augmente ; aujourd'hui un fichier par lecteur, écriture atomique et verrouillée (`_progress_lock`).
